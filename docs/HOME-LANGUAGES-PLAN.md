# Многоязычная главная — следующий пакет

Статус: согласовано владельцем25 октября2026, запланировано; ещё не реализовано.

Главная должна поддерживать несколько переводов одного оформления. JavaScript
переключает заголовок, вступление, подписи блоков **и адресаты ссылок**.
Например: русская кнопка «Мир» ведёт на отдельную точку `lore-ru`, английская
«World» — на `lore-en`. Это обязательное поведение, а не только перевод подписей.
Это настройка оболочки главной, а не языковые версии графа или сервера.

## Границы

- Точки остаются независимыми объектами на любом языке, с прежними ID/адресами,
  связями, авторами, подписками и влиянием. Никаких обязательных языковых
  суффиксов, пар переводов, фильтрации графа по языку или `/ru/` и `/en/` маршрутов.
- Переводы хранятся рядом с текущей home_page в репозитории или настройках сайта;
  существующий приоритет Git/UI/welcome применяется ко всему набору главной.
- У каждого языкового варианта блоков — свои ссылки на независимые точки нужного
  языка. При переключении обновляются и видимые подписи, и href/data-point-id.
  Нельзя оставлять прежний адресат под переведённой подписью, если для этого языка
  задана другая точка. Само переключение не создаёт и не переименовывает точки.
- Поддерживаются произвольные языковые метки, не только ru/en. Показывается один
  перевод за раз, без совмещённых двуязычных подписей. Бренд может быть общим.
- Выбор языка сохраняется локально. Первый выбор: доступный сохранённый язык,
  затем язык браузера, затем заданный владельцем язык по умолчанию. Отказ storage
  не должен ломать переключение. HTML lang обновляется вместе с видимым текстом.
- Если нужного перевода нет, целиком показывается главная на языке по умолчанию;
  не смешивать подписи одного языка и адресаты другого через поэлементный fallback.
  Каждый перевод задаёт полный набор своих блоков/ссылок. Общую нейтральную ссылку
  можно явно повторить в нескольких переводах; автоматических языковых пар нет.
- Без JavaScript отображается полноценная главная на языке по умолчанию.

## Порядок реализации

1. Совместимо расширить HomePage/RootHomePage и manifest schema: default_language
   и ограниченный набор переводов; существующие документы продолжают работать.
   Переводы содержат данные оформления и ссылки, без пользовательского JavaScript
   или произвольного HTML. Ограничения размеров/числа блоков действуют на весь набор.
2. Добавить Git-пример и редактирование переводов в «Мои сайты», сохранив проверки
   ревизий и явный выбор приоритета источника.
3. Общий renderer выводит исходную главную и безопасные данные переводов;
   общий JS-переключатель работает в hosted, iframe и статической копии.
4. Проверить ru/en/третий язык, пропущенные переводы, разные ссылки, отказ storage,
   мобильный экран и работу без JS. ID/общее соседство точек не должны меняться.

Переводы главной не включать в смысловой digest точек. Изменение перевода не
запускает голосование и не переносит поддержку; для самой главной применяется
существующая ревизия настроек. Содержание защищённых Git-точек меняется только
через их обычную Git-публикацию.
