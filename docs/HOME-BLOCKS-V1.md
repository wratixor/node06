# Главная страница входа: тематические блоки

Реализовано в исходниках; публикация требует слияния приложения в main и обычного
NODE06 deploy с миграциями `0006_home_page` и `0007_git_home`. Этот документ не подтверждает rollout.

## Что настраивает владелец

В `/sites/` выбрать свой сайт → «Главная страница» → выбрать источник.

| Режим | Откуда берётся страница |
|---|---|
| Авто | Принятая главная из Git → сохранённые настройки сайта → приветствие |
| Из репозитория | Только принятая Git-главная; если её нет — приветствие |
| Из настроек сайта | Только сохранённые UI-блоки; если их нет — приветствие |
| Только приветствие | Собственная приветственная точка без блоков |

Авто — значение по умолчанию для новых входов. Миграция сохраняет ранее заданные
UI-блоки с явным режимом `ui`, чтобы появление Git-главной не подменило сделанный
владельцем выбор. Выбор режима не удаляет ни один сохранённый вариант.

В режиме «Из настроек сайта» задать название, вступление, добавить блоки и ссылки,
затем «Сохранить главную». Для возврата к репозиторию выбрать Git или Авто и
сохранить. Редактор UI в остальных режимах скрыт; сохраняется
последний записанный UI-вариант, а не незавершённые правки выключенной формы.
Ссылкой рядом открыть сохранённый вид. Блоки можно перемещать выше/ниже и удалять;
ссылки добавлять/удалять независимо. В блоках можно смешивать любые языки.
Никаких ru/en маршрутов или соответствия «один язык — один блок» нет.
Например: механики, игры, мир, персонажи, справка.

Первоначальные пределы: 0–12 блоков, до 8 ссылок в каждом, до 12 KiB JSON данных.
Заголовки/подписи до 160 символов, описание блока до 1500, вступление до 2000.
Ссылки выбираются из публичного графа либо задаются внешним HTTP(S) адресом.
Сервис не запрашивает внешние адреса. HTML, CSS и скрипты в полях не исполняются.
Ссылки на точки — навигация: не создают смысловые рёбра, поддержку или влияние.

## Отдельно от Git-текстов

`sites.home_page` хранит конфигурацию в общей БД для конкретного входа. Настройку
может менять только активный владелец, в состояниях pending/active, даже если
приветствие Git-managed. Имена/ID/тексты/ревизии точек, Git-source и оформление
других входов не меняются. Деплой/публикация Markdown сохраняют настройку блоков.

`home_page=null` означает отсутствие сохранённого UI-варианта. Это само по себе
не отключает Git-главную в режиме Авто; для явного отключения блоков нужно выбрать
«Только приветствие». Если выбранному режиму не хватает источника, показывается
собственное приветствие, а не чужие зашитые корни. Для Git welcome ссылки безопасно отображаются с сохранением
текущего входа; UI welcome остаётся обычным экранированным текстом. Смена режима не удаляет точки или контент.

## Главная в репозитории

Опциональное поле `home_page` в `node06-roots.json` содержит те же title,
introduction, blocks и links. Например, рядом с объявленным локальным корнем:

```json
"home_page": {
  "title": "Игры и мир",
  "blocks": [{
    "title": "Игры",
    "links": [{"label": "Каталог", "point_id": "local/games-ru"}]
  }]
}
```

`local/<id>` разрешается в site-scoped ID корня текущего manifest;
`local/welcome` — в существующую точку входа. Необъявленный локальный ID
отклоняется preflight. Можно использовать обычные глобальные point_id и внешние
HTTP(S) URL. Это навигация, а не смысловые рёбра или revision-pinned цитаты.
После раскрытия локальных ссылок действует тот же бюджет 12 KiB; сам manifest
по-прежнему ограничен 16 KiB. Пример полного source находится в `examples/root-source/`.

Preflight включает главную в immutable candidate digest, не меняя meaning digests
точек. Принятый снимок `sites.git_home_page` обновляется атомарно вместе с root
publication; `home_page_source` и сохранённый `home_page` не перезаписываются.
Изменение только layout не создаёт семантические ревизии точек. Удаление/null поля
в успешно опубликованном manifest очищает Git-снимок, затем действует таблица
приоритетов выше. Ошибка fetch/валидации не очищает последний принятый снимок.
Произвольные index.html, JS, шаблоны и hooks из контентного source не исполняются.

Порядок релиза: сначала слить поддержку Git-home в application main, затем
контентный manifest с новым полем в content main; после этого обычный NODE06 deploy.
Старый publisher отвергнет неизвестное поле; не публиковать новый manifest раньше
готовности application main. Новый deploy-toolkit для этого пакета не требуется.

## Публичное отображение и границы

Hosted `/`, `/sites/{site_id}/` и full iframe `/embed/v1/{site_id}/` показывают
главную без автоматического открытия карты. `?p=...&open=...` по-прежнему открывает
точку. Заголовок/ссылка HOME возвращает к стартовой странице текущего входа.
Внутренние ссылки сохраняют field path, включая iframe; внешние открываются в
новой вкладке с noopener/noreferrer. Блоки адаптируются к ширине окна.

Самостоятельный статический HTML Neocities не переписывается сервером. Общая
главная доступна через full iframe; собственный интерфейс может прочесть поле
`home_page` в публичном site API через уже существующий разрешённый bridge.
Рендерер собственных статических страниц/автоматическая замена их HTML в этом
пакете не добавляются. Обычный офлайн NODE06 сохраняет свою текущую главную.

## HTTP-контракт и конфликты

`GET /api/v1/sites/{id}/manage` и публичный site response содержат сохранённый
UI-вариант `home_page`, принятый `git_home_page`, выбор `home_page_source`, а также
вычисленные `effective_home_page` и `effective_home_source`. Все эти настройки
публичны; не хранить в них секреты. Собственным клиентам нужно отображать effective
вариант. Обычный `home_page` сохраняет первоначальный смысл UI-поля для совместимости.
`PUT /api/v1/sites/{id}/home` принимает:

```json
{
  "expected_settings_revision": 3,
  "home_page_source": "ui",
  "home_page": {
    "title": "Игры и мир",
    "introduction": "Выберите интересующий аспект",
    "blocks": [
      {"title": "Механики", "description": "Правила и навыки",
       "links": [{"label": "Навыки", "point_id": "skills-ru"}]},
      {"title": "Играть", "links": [{"label": "Arena", "url": "https://arena.geno-dice.com/"}]}
    ]
  }
}
```

Для старых запросов без `home_page_source`: непустой UI-layout выбирает `ui`,
null выбирает `welcome`, сохраняя прежнюю семантику явного сохранения/reset.

Каждая ссылка задаёт ровно один из `point_id`/`url`. Неизвестные поля,
небезопасные URL, ссылки с credentials, неправильные ID и превышения отклоняются.
ID — устойчивая ссылка; исчезнувшая/неопубликованная точка не удаляет настройку
и не подменяется другой. Редактор отмечает недоступный текущий выбор в списке.

Требуются HTTPS management origin, сессия владельца, CSRF и проверка ревизии.
На embed origin управление заблокировано. Ответы приватных методов — no-store.
Изменение атомарно увеличивает settings revision и пишет `site_home_updated`;
повтор идентичной настройки — no-op. Семантические ревизии точек не создаются.

При 409 редактор сохраняет ввод, показывает серверный вариант и предлагает
явно загрузить его либо после сравнения сохранить свой. Повторное сохранение
снова проверяет свежую ревизию. Редакторы текста/темы и главной имеют отдельные
черновики; изменение настроек в другом редакторе может вызвать такой же 409.
При сетевой/сессионной ошибке блоки не очищаются. Полная перезагрузка страницы
не является системой сохранения неопубликованных черновиков.

## Проверки и rollout

PostgreSQL-тесты покрывают владельца/сессию/CSRF/origin, Git welcome, no-op,
конфликты, reset, ограничения, безопасный HTML, сохранение при root publication,
онлайн downgrade/upgrade и scoped hosted/embed ссылки. Дополнительные fixtures
проверяют локальные Git-ссылки, неизменность candidate/meaning digests, режимы,
сохранение обоих вариантов, удаления Git-layout, миграцию старого UI-выбора и
проверку ревизии при гонке публикации с настройкой источника. Локальный браузерный стенд
с фиктивным API проверяет ввод/выбор точек/сохранение и визуальный вид двух блоков;
это не production browser acceptance. API отдельно проверяется на реальной
мигрированной disposable PostgreSQL через psycopg.

После слияния: обычный `deploy-all.sh --host geno-dice --project node06`, затем
проверить `/sites/`, `site_home_blocks` / `git_home_priority` в meta, главную и deep links в hosted/full
iframe. Повторная регистрация/смена iframe ID не нужны. Не откатывать схему с
настроенными блоками без backup и отдельного решения: downgrade удаляет колонку.


## Ссылка в углу серверной вики

На серверной копии название в левом углу всегда ведёт на `/` этой вики, в том
числе со страниц `/sites/<id>/` других подключённых сайтов. Его задаёт
`home_page.title` главной точки сервера, выбранной через `NODE06_DEFAULT_SITE_ID`,
с обычным приоритетом Git/Авто/UI. Для Geno-Dice Wiki поле уже находится в
`geno-dice-wiki/node06-roots.json` и равно `Geno-Dice: Wiki`. После публикации
репозитория изменение названия применяется и к угловой ссылке. При отсутствии
блоков используется имя главного сайта, затем название оператора.

Открытая точка другого сайта сохраняет собственную главную и содержимое. Во
встроенном полном iframe ссылка в углу ведёт к его собственной точке входа;
у статического NODE06 на Neocities ссылка по-прежнему ведёт на его `/`.

## Полные переводы главной (25 октября 2026)

В исходниках поддержаны `default_language` и `translations`; для этого расширения
не нужна новая миграция. Текст верхнего уровня — основной вариант, а каждый
элемент `translations` — самостоятельный полный вариант с собственными блоками,
подписями и адресатами. Это перевод оформления главной, не локализация графа.

```json
{
  "default_language": "ru",
  "title": "Мир",
  "entrance_label": "Точка входа",
  "all_sites_label": "Все сайты",
  "blocks": [{"title": "Мир", "links": [{"label": "Открыть мир", "point_id": "lore-ru"}]}],
  "translations": {
    "en": {
      "title": "World",
      "blocks": [{"title": "World", "links": [{"label": "Open world", "point_id": "lore-en"}]}]
    }
  }
}
```

В Git допускаются те же поля и `local/<id>` в **каждом** переводе. Пример:
[examples/root-source/node06-roots.json](../examples/root-source/node06-roots.json).
`entrance_label` и `all_sites_label` задают подписи служебных ссылок; по умолчанию
они английские. Для других языков владелец переводит их явно. Варианты не наследуют
друг у друга текст, блоки и ссылки. Без `default_language` используется `und`;
старый документ остаётся одноязычным без переключателя. Совпадающие без учёта
регистра языковые метки запрещены. Метка может быть, например, `ru`, `ja`, `pt-BR`.

В «Мои сайты» → «Главная страница» → «Из настроек сайта» можно добавить язык,
переключаться между несохранёнными вариантами, назначить основной и удалить
неосновной. Сначала переключатель сохраняет поля текущего варианта в форме.
Одна кнопка сохранения отправляет весь набор с прежней проверкой settings revision;
при конфликте переводы остаются в форме для сравнения. Приоритет Git/UI/welcome
по-прежнему выбирает **весь набор**, не отдельные языки из разных источников.

Пределы действуют суммарно: основной + до 8 переводов, до 12 блоков на весь набор,
до 8 ссылок на блок, 12 KiB JSON UTF-8 включая переводы и служебные поля.
У старого одноязычного `und`-документа добавленные служебные значения по
умолчанию не отнимают прежний бюджет: весь ранее допустимый диапазон сохраняется,
включая повторное чтение нормализованного JSON.
Произвольные HTML/JS, небезопасные адреса и вложенные переводы не принимаются.
Домашние переводы не создают рёбра, смысловые версии точек или голосования.

Сервис и статическая сборка используют общий escaped HTML renderer и внешний
`assets/home-languages.js`. В DOM уже находятся полные безопасно экранированные
варианты; JS переключает целый видимый вариант вместе с href/data-point-id.
Без JS основной вариант доступен сразу, переключатель скрыт; HTML lang у hosted
соответствует основному языку. С JS lang меняется вместе с вариантом.

Выбор: доступный сохранённый язык → первый подходящий язык браузера → основной.
Для браузерных меток проверяется точное совпадение, затем родительская метка
(например en-US → en). Сохранённый выбор действует только в текущем origin и для
конкретного входа (`node06.home-language.<site_id>`; `static` у статической копии).
Потеря localStorage не мешает текущему переключению; другой origin/iframe может
иметь своё изолированное предпочтение. URL главной не меняется при выборе языка.

NODE06 static home теперь имеет отдельные ru/en варианты со ссылками на прежние
независимые точки и отдельные инструкции установки; константа в `build.py`
настраивается в форке. Никаких языковых пар/переименований в графе не добавлено.
Существующий Git manifest Geno-Dice Wiki сам собой не переводится: после релиза
движка нужно отдельно задать его варианты в контентном репозитории. Первая
публикация старого home после обновления может нормализовать новые default-поля
настроек, не создавая смысловых ревизий точек.

Проверки: `backend/tests/test_home_languages.py`,
`NODE06_HOME_ONLY=1 .venv/bin/python scripts/check-hosted-browser.py` с disposable
PostgreSQL и Playwright; тот же browser packet включён в полный hosted прогон.
Статическая навигация проверяет переключение и прежние ID/соседство всех корней.
Деплой: обычное обновление движка и rebuild static; новая миграция не требуется.
