# Следующий пакет: 30 суток скрытия и tombstone

Статус: исторический аудит перед реализацией, 24 октября 2026.
Реализация25 октября: [CONTENT-PURGE-V1](CONTENT-PURGE-V1.md).
Ниже сохранены исходный аудит и критерии; актуальный контракт — по ссылке.

## Утверждённое правило

Только непрерывное серверное скрытие запускает30 суток. Локальное скрытие сайта
и бан/карантин сами по себе не запускают удаление. Восстановление до срока
отменяет отсчёт. После срока содержимое удаляется, ID точки остаётся пустой
отметкой, чтобы ссылки сохраняли адресата. Повторное скрытие уже скрытой точки
не продлевает срок; новое скрытие после восстановления начинает новый срок.

## Проверено по исходникам

`moderation._visibility` уже сохраняет `point_hides.hidden_since` при повторном
скрытии и очищает его при восстановлении. `social_worker.run` выполняет
ограниченную фоновую работу каждые30 секунд. В модели `points.lifecycle` сейчас
только active/inactive/retired; отдельного состояния окончательной очистки нет.
`visibility.visible/hidden_ids` не содержит tombstone-проверки.

| Хранилище | Что нужно учесть |
| --- | --- |
| point_revisions | Все body и search_text, а не только текущая ревизия. search_text имеет insert-default, поэтому очистка body сама его не обнулит. |
| authored_revisions.citations | JSON-снимки static_body коренной точки, включая цитаты этой точки в чужих ревизиях. |
| subscriptions / point_blocks | static_body для коренных точек; ссылки на revision_id должны оставаться непротиворечивыми. |
| proposals | base_body, content.body, citations[].static_body и кандидат в point_revisions; открытое предложение не должно воскресить текст. |
| core_publications | body корней текущей сборки: синхронизация core не должна заполнить очищенное содержимое заново. |
| sites | home_page и git_home_page требуют отдельной обработки, если удаляется точка входа сайта; это самостоятельные JSON-документы, не просто revision.body. |
| events / social_events / point_operations | Проверить форму payload/response каждого производителя. Текущая авторская публикация пишет ID ревизий, а не текст; удалять все события без разбора нельзя. |
| influence_runs | Проверить проекции/свежесть и инвалидировать расчёт; наличие JSON не означает, что там хранится тело текста. |

Подписки, история поддержки и другие таблицы с RESTRICT-ссылками не позволяют
просто удалить связанные ревизии без отдельного решения. Предпочтительный
вариант для реализации: сохранить ID ревизий, обнулить текст и поисковую копию;
сохранить только необходимую историю ID/хешей/аудита. Очистку цитат выполнять
по ID адресата, не глобальной заменой похожих строк в чужих авторских текстах.

## Порядок реализации

1. Отдельная постоянная запись tombstone с временем очистки. Не использовать
   retired как достаточную защиту: это состояние уже применяется импортом.
2. В одной транзакции под существующей блокировкой графа заново проверить
   актуальное серверное скрытие и срок через часы PostgreSQL после ожидания
   блокировки. Очистить все структурированные копии, закрыть предложения и
   сохранить ID/audit. Повторный запуск должен быть безопасным.
3. Защитить public API, поиск, граф, историю, библиотеку, карантин и модераторское
   чтение. Последнее тоже не должно показывать очищенный текст. В частности,
   PublicPoints.raw_on сначала проверяет tombstone, даже при moderation=False,
   затем может обращаться к корням сборки.
4. Не позволять core/Git-публикации, старому receipt или восстановлению скрытия
   автоматически заполнить очищенный ID. Git-репозиторий не переписывать.
5. Добавить ограниченный фоновый проход в существующий worker и наблюдаемое
   состояние ошибки; не выполнять удаление в обработчике обычного GET.
6. Обеспечить пустую публичную отметку без приватной причины, обновление T1/
   геометрии, документацию оператора и проверку установленного wheel.

## Обязательные проверки перед включением

- 30 суток ровно, срок до/после границы, site-only hide, повторное скрытие,
восстановление до срока и повторное скрытие после восстановления.
- Два worker, restore/purge и publish/purge под конкуренцией, перезапуск после
сбоя, повторный проход без новых побочных эффектов.
- Все ревизии и встроенные снимки корней исчезли из поисковых и читающих путей;
чужой текст и несвязанные JSON-поля сохранены.
- Модератор/карантин/история не обходят tombstone; Git/core/receipt не воскрешают
очищенный текст. Ссылки продолжают указывать на прежний ID.
- Онлайн-миграция на одноразовом PostgreSQL с реальным драйвером проекта.

Резервные копии подчиняются отдельной политике хранения. Этот пакет не удаляет
исходный Git, независимые Neocities-копии, чужие кэши и чужие серверы. После
восстановления старой БД оператор должен учитывать утраченные после снимка
решения модерации; это не обещание очистить независимые архивы автоматически.
