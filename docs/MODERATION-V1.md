# Жалобы и скрытие по области v1

Реализовано в исходниках. Деплой и выдача первого серверного доступа отдельно.
Миграция: `0016_scoped_moderation` после0015. Политика следующих этапов:
[MODERATION-PLAN](MODERATION-PLAN.md).

## Полномочия

Область — `server` или ID активного сайта `s_<uuid>`. Владелец активного сайта
имеет права администратора своей области. Редактор контента не получает
модерацию автоматически. Явно назначенный модератор может смотреть жалобы,
скрывать/восстанавливать точки и закрывать случаи; администратор также назначает
и отзывает роли в своей области. Серверная роль действует на сервере и его
сайтах. Серверный модератор не может делегировать серверные права. Администратор
сайта не может назначить серверную роль. Владелец сайта сохраняет свои права,
даже если явное назначение удалено; собственную роль через UI менять нельзя.

Первого серверного администратора назначает оператор существующему активному
аккаунту **по точному ID**, не по имени, порядку регистрации или владению сайтом:

```sh
python -m node06_service.moderation_admin --user-id u_<32_hex> --role admin
```

Команду запускают в настроенном окружении сервиса с приватным
`NODE06_DATABASE_URL` и миграцией0016. Не передавать DSN/пароли в Git или чат.
CLI пишет аудит с actor=NULL и действием bootstrap. Он не запускается при
старте сервиса и не выполнялся на production в рамках разработки.
Назначения и отзыв через UI требуют действующей сессии, CSRF и прав области.
Каждый mutation повторно проверяет сессию и роль под общей блокировкой графа;
отозванная роль не позволяет повторить даже старую квитанцию операции.

## Жалобы и панель

Значок флага на точке открывает доверенную страницу `/moderation/?point=…&scope=…`.
На внешнем сайте это отдельная first-party страница; личные сессии и сообщения
не попадают в iframe. В личной навигации появился раздел «Жалобы».
Обычный пользователь видит форму жалобы, ответственный — очередь своей области.

Один случай на точку/область, счётчик **уникальных заявителей**. Повторные запросы
и другая причина от того же аккаунта не раздувают число и не создают сообщений.
Причина первого обращения сохраняется. После закрытия новое обращение другого
человека возвращает случай в открытые; повтор старого заявителя не открывает.
Закрытие жалобы не скрывает точку, восстановление не закрывает жалобу автоматически.

Очередь имеет страницы до30 случаев и отдельные открытые/закрытые состояния.
При разборе доступны текущий текст, первые30 причин (с отметкой о продолжении),
статус скрытия и последние20 записей аудита. В БД сохраняются все обращения и
весь аудит; полный просмотр оставшихся причин/аудита ещё требует отдельной
пагинации. Нельзя считать текущую панель полным экспортом журнала.

## Скрытие и время

Скрытие в области сайта убирает точку только из его представления. На другом
сайте и в общем графе она остаётся доступной. Это локальное правило отображения,
не секретность текста: читатель может перейти в другой вход.
Серверное скрытие обязательно во всех представлениях сервера. Оно не удаляет
ревизии, голоса, доверие, подписки или исходный Git. Повторное скрытие активной
записи не сбрасывает `hidden_since`. Восстановление очищает время; новый цикл
начинается с нового времени. Только `scope=server` может стать основанием
будущего удаления после30 суток.

**Автоматического удаления, tombstone-публикации и банов в этом пакете нет.**
Дата серверного скрытия сохраняется для следующего этапа, ничего не стирает.
История решений содержит автора, время, действие и причину; сетевой повтор с
тем же Idempotency-Key не добавляет аудит заново. Ключ привязан к актору и данным,
конфликт возвращает409. После неопределённого сетевого результата UI предлагает
повторить то же действие; менять его данные до завершения нельзя.

## Общий фильтр чтения

`PublicPoints` учитывает серверное скрытие всегда, в том числе для встроенных
статических roots. Поиск, соседи, история, social-summary, публичные авторские
точки, геометрия, лента, previews личных списков и события не выдают скрытый текст.
В личных списках подписка/избранное могут оставаться с ID и пустым preview.
Hosted-карта фильтрует accepted Git, пользовательские точки, статические seeds
и ссылки на них. Скрытое приветствие не выдаётся через HTML входа или публичные
метаданные сайта. Legacy и current iframe reads используют ту же область сайта.
Git-обновление и повторный импорт не удаляют записи скрытия.

Явный параметр `site=s_<uuid>` выбирает представление в public API; без него
используется настроенный default-site, иначе серверный граф. Hosted shell
передаёт свою область карте и public picker. Смена site никогда не отменяет
серверное скрытие. Право на просмотр скрытого текста даёт только отдельный
защищённый inspect после проверки роли; параметра bypass в публичном API нет.

Независимая скачанная статическая копия (включая Markdown/HTML на Neocities),
чужой Git или кэш уже содержат старый текст. Наш сервер не может изъять его.
Гарантия относится к текущим чтениям управляемого hosted/API/bridge; статический
fallback внутри этих серверных чтений тоже фильтруется. Это не обещание удаления
из чужих файлов или уже открытой страницы без повторной загрузки.

## HTTP

Все пути ниже — first-party `/api/v1/moderation`, no-store и запрет framing;
embed-host возвращает404 независимо от cookie.

- `GET /scopes` — свои назначения и принадлежащие активные сайты.
- `GET /cases?scope=…&status=open|closed&after=…` — очередь30 и next_cursor.
- `GET /inspect/{point_id}?scope=…` — защищённый разбор.
- `POST /reports/{point_id}?scope=…` с `{reason}` — жалоба на публичную точку.
- `POST /visibility/{point_id}?scope=…` с `{hidden,reason}` — решение.
- `POST /cases/{point_id}/close?scope=…` — закрыть случай.
- `POST /roles/{user_id}?scope=…` с `{role: admin|moderator|null}` — назначить/отозвать.

Записи ограничены сессией/CSRF/origin, фактическим размером body и лимитами
120 действий на пользователя и240 на IP за час; причина до2000 символов,
не пустая. Idempotency-Key обязателен. Для чтения отсутствует анонимный доступ.

## Выпуск и откат

Обычный backup-first deploy применяет Alembic upgrade head; затем оператор
назначает конкретный серверный аккаунт. Для владельцев активных сайтов
отдельная первоначальная выдача не нужна. Обновление не меняет тексты и T1.
Downgrade до0015 удаляет роли, жалобы, аудит и скрытия, **снова делая скрытые
точки видимыми**. Предпочтителен откат приложения с сохранением таблиц и
закрытием публичного доступа до решения оператора; само старое приложение
не умеет учитывать фильтр. Downgrade не является безопасным способом отмены
модерации без проверки оператора. Проверять на отдельной PostgreSQL через
производственный psycopg-драйвер, включая populated upgrade/downgrade/re-upgrade.

## Поиск пользователей

В панели добавлен scoped поиск пользователей с датой регистрации и состоянием,
ссылкой на профиль/посты и выбором ID для существующей формы назначения доступа.
Проверка роли повторяется на каждом чтении, включая страницы списка.
`GET /users?scope=…&q=…&after=…`:20 записей и `next_cursor`; подробности и
публичные рейтинги: [DIRECTORY-V1](DIRECTORY-V1.md). Новых привилегий и миграций нет.
