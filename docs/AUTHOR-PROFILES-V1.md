# Профиль автора и подписка

Имя автора пользовательской точки ведёт на `/people/u_<id>/` на доверенном
сервере. У системных точек и Git-корней без зарегистрированного автора остаётся
атрибуция источника; личность не выдумывается. Из внешней копии ссылка открывает
доверенный сайт отдельно. Публичный профиль показывает имя, цвет и видимые точки
автора, с продолжением списка. Скрытые/неактивные точки и закрытые настройки
в этот список не попадают.

## Подписка и блокировка

По решению владельца подписка на автора **равна доверию T1**. Кнопки подписки и
отписки используют существующий `/api/v1/people/{id}/trust`; это тот же граф
доверия, без второго бюджета или параллельной социальной связи. Публичный профиль
не раскрывает чужой список доверия, подписчиков или заблокированных людей.

Блокировка автора атомарно удаляет исходящее доверие к нему и сохраняет личную
блокировку. Она скрывает из личной ленты события, у которых автор события или
автор точки заблокирован. Сами события не удаляются: после разблокировки они
снова доступны по обычной пагинации. Публичные URL автора и его точек остаются
доступными при явном открытии.

Блокировка не создаёт отрицательного доверия и не меняет реакции на каждую
точку автора. Существующие подписки/блокировки точек остаются как были. Повторная
подписка на заблокированного автора отклоняется (`AUTHOR_BLOCKED`), пока человек
явно не разблокирует его. Разблокировка не возвращает доверие автоматически.
Подписаться на себя и заблокировать себя нельзя. Разделы личного профиля содержат
ссылки на авторов и список блокировок с возможностью снять их.

Личная лента создания использует текущее T1-доверие к авторам вместе с подписками
на связанные точки; версии и предложения остаются отдельными уведомлениями.
История подгружается по непустым дням. См. [CREATION-FEED-V1](CREATION-FEED-V1.md).

## API и границы

- `GET /api/v1/people/{id}` — публичные `id`, `handle`, `color`.
- `GET /api/v1/people/{id}/points?after=…` — до20 видимых точек и курсор.
- `GET /api/v1/me/people/{id}` — личные флаги `following`, `blocked`.
- `GET /api/v1/me/people/blocks?after=…` — до30 личных блокировок и курсор.
- `POST /api/v1/people/{id}/block` с `{active: bool}` — личная блокировка.
- `GET /api/v1/me/social` сохраняет массив `trust` и добавляет `trust_profiles`
  с публичными именами для этих ID.

Записи используют существующие сессию, CSRF, лимиты, блокировку графа и журнал
идемпотентных операций. Неопределённый ответ повторяется с тем же ключом и
неизменным действием; смена аккаунта блокирует повтор. Приватные API и HTML
управления отсутствуют на embed-origin. Профиль не разрешён к встраиванию.
Публичная social-summary теперь включает уже публичный ID автора для ссылки;
ID участников реакций/голосований по-прежнему не раскрываются.

## Миграция и выпуск

`0014_user_blocks` добавляет только таблицу исходящих блокировок пользователей.
Существующие точки, подписки, доверие, история и расчёт T1 не переписываются.
Перед обновлением нужен обычный backup-first деплой с Alembic upgrade head.
Откат приложения с сохранением таблицы предпочтителен. Downgrade до0013 удалит
личные блокировки, но не восстановит снятое доверие и не удалит посты/историю.
Проверка обновления и downgrade/re-upgrade выполняется через production-диалект
SQLAlchemy/psycopg на отдельной PostgreSQL-базе с опубликованной точкой и блоком.
