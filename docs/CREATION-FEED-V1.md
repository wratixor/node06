# Лента создания точек v1

Реализована в исходниках. Публикация на сервере проверяется отдельно.

## Состав

Один личный поток: новые точки доверенных авторов (подписка на автора = T1)
или точки, при создании связанные с точкой активной подписки пользователя.
Совпадение обоих условий даёт одну запись. Личные блокировки авторов и точек,
публичная видимость и lifecycle применяются при каждом чтении.

Дата события — неизменный `points.created_at`; исходные связи берутся из первой
сохранённой ревизии. Последующее добавление связи не создаёт событие задним числом.
Превью показывает текущий публичный текст. Правки, голосования, изменение цвета
и поддержка не поднимают точку и не создают новые записи. Подписки проверяются
текущие: подключившись к автору/теме, можно отмотать их историю. Это не журнал
того, что конкретный пользователь видел в момент создания.

Существующие уведомления о предложениях и версиях сохранены отдельно в разделе
«Уведомления» (`#inbox`). Лента находится в `#feed` и в режиме FEED карты.

## Даты и API

`GET /api/v1/me/feed?cursor=…&limit=20` — first-party личный read.
Сессия обязательна; обычные ограничения origin и management-host сохраняются.
Ответ: `viewer_id`, `day`, `items`, `next_cursor`, `next_day`. Лимит1–30.
Одна страница содержит только один непустой день UTC, до лимита записей.
При большом дне следующая страница остаётся в нём. Кнопка «Раньше» показывает
дату следующего непустого дня; пустые даты не перечисляются. Старые тела точек
загружаются только при переходе назад. «Новые» начинает просмотр заново.
Дополнительный `before_day=YYYY-MM-DD` выбирает ближайший непустой день не позже
указанного; одновременно с cursor использовать нельзя.

Keyset-порядок: создание DESC, ID в C collation DESC. Курсор привязан к аккаунту
и верхней границе первой страницы, не является разрешением доступа и не заменяет
проверку видимости. Это не замороженный снимок: изменение подписок, блокировок
или публикации меняет доступные результаты. Курсор не подписан; его изменение
не позволяет читать чужие подписки или закрытые точки.

Git-публикации и сайт-точки с реальной публичной ревизией также участвуют.
Ленивые ссылки на статические roots без опубликованной ревизии не синтезируют
события создания. Массовый импорт в один день может дать несколько страниц.

## Границы и выпуск

Внешние статические копии и full iframe предлагают открыть личную ленту на
доверенном сервере. Они не читают личные API, не получают списки подписок,
сессии или новые authenticated bridge capabilities. Гостю предлагается вход.

Миграция `0015_creation_feed` добавляет индекс даты/ID; данные не переписывает.
Обычный backup-first деплой применяет Alembic upgrade head. Откат до0014 удаляет
только индекс; приложение без этого маршрута можно вернуть без удаления данных.
Проверки: PostgreSQL фильтрация/история/курсор/блокировки/обновления и populated
upgrade/downgrade/re-upgrade; HTTPS Chromium проверяет отдельный раздел и цвет.
