# Пользователи и рейтинги

`/directory/` — общедоступная страница поиска пользователей и просмотра влияния.
Ссылки ведут в существующий профиль `/people/{id}/` с постами автора и действиями
подписки/блокировки. Доверие T1 и личные блокировки не меняются этим пакетом.
Каталог доступен в личной навигации и через ссылку на доверенный сервер в статике.
Страница не встраивается в iframe; на embed-host отсутствует.

## Публичные чтения

- `GET /api/v1/directory/users?q=…&after=…`: поиск подстроки имени без учёта
  регистра, `%` и `_` трактуются буквально. Пустой запрос перечисляет активных
  пользователей. Только `{id,handle}`, до20 записей, `next_cursor` — последний ID,
  порядок по ID. Для смены запроса курсор сбрасывается.
- `GET /api/v1/directory/rankings?kind=users|points&after=…`: до20 результатов,
  по убыванию целочисленного T1 с одинаковыми значениями по ID. Пользователи —
  общий вес `weights`; точки — **положительная подтверждённая поддержка текущего
  текста** `point_mass.current`. Нулевая поддержка, held и блокировки не входят
  в рейтинг точек. Это рейтинг поддерживаемых точек, не список всего графа.
- Вес передаётся десятичной строкой из существующего fixed-point расчёта.
  Результат не содержит доверительные рёбра, личные подписки, блокировки,
  аллокации, пароли, почту, IP, сессии или аварийные коды.
- Рейтинг читает сохранённый `influence_runs`, не запускает пересчёт на GET.
  Нет расчёта/не совпадают активные аккаунты или cutoff событий — `pending:true`
  и пустой список. Для выдаваемых точек сверяются revision/digest; устаревший текст
  также даёт pending. Перед ответом повторно проверяется cutoff событий.
- Курсор связан с ID расчёта и видом рейтинга. После смены расчёта —409
  `RANKING_CHANGED`: начать заново. Не смешивать страницы разных расчётов.
  Видимость проверяется заново на каждой странице, включая static-root fallback.
  Применяется выбранный/default site, серверные скрытия действуют всегда.
- За запрос проверяется максимум100 кандидатов. При множестве скрытых точек
  страница может быть пустой с `next_cursor`; кнопку «Ещё» сохранять.
- Чтение анонимное, `no-store`, только management-origin. Query ограничен64
  символами, выдача ограничена размером общего публичного ответа255KiB.

## Приватная панель

`/moderation/` содержит поиск пользователей в выбранной области.
`GET /api/v1/moderation/users?scope=server|s_<id>&q=…&after=…` на каждом запросе
проверяет действующую сессию и полномочия в области. Возвращает до20 записей,
включая отключённые: `{id,handle,created_at,state}`; даты в ISO UTC из БД.
Эти поля **не добавляются** в общедоступный профиль/каталог пользователей.
Для отключённых аккаунтов показаны имя/ID и состояние; публичный профиль
и назначение доступа недоступны. Публичное время `created_at` рейтинга
означает время расчёта, не регистрации.

Модератор видит результаты и ссылки на профили. Администратор дополнительно
может подставить ID найденного пользователя в существующую форму доступа.
Это ещё не выдача роли: требуется отдельное «Применить», с прежними CSRF,
идемпотентностью и проверкой полномочий под блокировкой. Назначение отключённому
пользователю по-прежнему запрещено сервером. После отзыва роли новый запрос
отклоняется; приватный список очищается при403/401 или смене области/аккаунта.

Поля области и статуса жалоб с кнопкой выровнены по нижнему краю на широком
экране; при ширине≤520px область занимает свою строку. Поиск и длинные ID
переносятся без горизонтального переполнения.

Новых таблиц, миграций, зависимостей, производственных назначений и изменений
формулы влияния нет. После слияния — обычный деплой приложения и статики.
Баны, общий карантин и удаление через30 суток остаются следующими пакетами.
