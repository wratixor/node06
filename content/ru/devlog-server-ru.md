Этап 4. Независимая копия сервера

Если нужна своя база и собственные правила управления, копия репозитория NODE06 может работать независимо от исходного владельца. Это уже другой сервер: аккаунты регистрируются в нём отдельно, влияние не переносится с соседних серверов. О принципе общего пространства внутри одной базы — в точке [NODE06](md://node06-ru).

Для backend нужны Python версии не ниже 3.12 и ниже 3.15, PostgreSQL и зависимости pyproject.toml. Установка в виртуальное окружение, статическая сборка и запуск сервиса описаны в инструкции. Статическая копия без backend собирается отдельно командой python3 build.py; это не установка базы и не запуск социальной части.

Для серверной копии задайте приватное окружение по backend/.env.example. Основные параметры: NODE06_DATABASE_URL, NODE06_MANAGEMENT_ORIGIN, NODE06_EMBED_ORIGIN и NODE06_HOSTED_DIST. Доверенная вики и embed используют разные HTTPS-origin. Пароли БД, cookies, резервные копии и приватный конфиг не входят в публичный репозиторий или dist/.

Порядок обновления: резервная копия и проверяемая процедура восстановления, установка выбранной ревизии, все её миграции через alembic upgrade head, затем запуск за HTTPS reverse proxy. /api/v1/health проверяет процесс, /api/v1/ready — доступность БД; одна готовность не доказывает правильный migration head. /api/v1/meta показывает сборку и возможности. После обновления отдельно проверяются вход, создание точки и чтение из подключённого сайта.

Автообновление контентного Git-источника не обновляет сам движок. Свой форк выбирает политику обновлений. Откат приложения не означает безопасный откат схемы: после необратимого удаления содержимого защитные отметки нельзя просто убрать миграцией назад. Это инструкция по текущим исходникам, а не отчёт об установке на вашем сервере.
